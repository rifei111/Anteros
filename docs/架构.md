# 架构

Anteros 是单机桌面应用。三层：**内核**（唯一写数据库的人）、**主客户端**（Electron）、
**插件**（独立进程，能力受 manifest + 授权约束）。

## 1. 进程与边界

```
┌──────────────────── Electron 主进程 ────────────────────┐
│  Renderer（React，sandbox，无 Node）                     │
│      │  contextBridge / ipcRenderer.invoke               │
│      ▼                                                   │
│  Main（窗口、单实例锁、IPC 桥、内核守护）                 │
│      │                                                   │
│      │ net.connect 命名管道 + NDJSON/JSON-RPC            │
└──────┼───────────────────────────────────────────────────┘
       ▼
┌────────────────────── 内核进程 ──────────────────────┐
│  Kernel（node dist/kernel.mjs，ELECTRON_RUN_AS_NODE） │
│  SQLite / 记忆 / 调度 / 成本 / 授权 / 插件宿主         │
│      │ spawn + 每插件一条命名管道                     │
│      ▼                                                │
│  Plugin 进程 × N（每插件一个 Node 进程）               │
└──────────────────────────────────────────────────────┘
```

- **内核**：`packages/kernel/src`，esbuild 打成 `packages/kernel/dist/kernel.mjs`，
  **独立子进程**运行（`ELECTRON_RUN_AS_NODE=1`）。启动后向 stdout 打一行 `{"type":"ready","pipeName",...}`，
  主进程据此连管道。它拥有 SQLite、调度、记忆、成本、授权与插件宿主，不 import electron。
- **主客户端**：`packages/client/src/main` 负责窗口/生命周期与内核守护，`preload` 暴露白名单 IPC，
  `renderer` 是纯 React（`sandbox: true`、`contextIsolation: true`）。页面拿不到内核管道名与 token。
- **插件**：`plugins/<id>`，内核用 `process.execPath` 拉起独立进程，环境变量注入管道名/一次性 token/数据目录。
  插件不 import 内核代码、拿不到数据库路径。

启动时序（`packages/kernel/src/main.ts`）：

1. `bootstrap()` 打开/迁移 SQLite、装载设置、种子数据（user/persona/agent/relation/drives/presence/meta）；
2. `new App(...)` 组装服务与插件宿主（此时**不拉起**任何插件进程）；
3. `IpcServer.start()` 建命名管道；stdout 打一行 `ready`（同时含 `event:"ready"` 与 `type:"ready"` 以兼容两种读法）；
4. `void app.start()`：`plugins.start()` 扫描 `plugins/` → 校验 manifest → 对 `enabled` 且已过声明闸的插件握手拉起；
   `channels.start()` 启动入站轮询。**拉起失败只告警，不影响内核与人对话**；
5. 首启用例：未过声明闸时默认插件保留 `enabled=1` 但状态 `blocked`，`consent.accept` 成功后自动补启动
   （`resumePluginsAfterConsent()`），不需要重启应用。

## 2. 三条 IPC

| 链路 | 载体 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| Renderer ↔ Main | Electron IPC（`contextBridge` 白名单） | 同进程 | 页面只能调 preload 暴露的方法 |
| Main ↔ Kernel | Windows 命名管道，NDJSON 帧，JSON-RPC 2.0 | 每帧顶层 `auth === token` | 内核由主进程拉起；token 随机生成，只在内核 env 与主进程内存里 |
| Kernel ↔ Plugin | Windows 命名管道，NDJSON 帧，JSON-RPC 2.0 | 每帧顶层 `auth === token` | 管道名 `\\.\pipe\anteros-kernel-<session>-<pluginId>`；单帧上限 8MB |

插件协议要点（规范 6）：

- 首帧 `plugin.handshake {pluginId, kernelApi, capabilities, auth}`，内核回 `{kernelApi, sessionId, grants}`；
  主版本不符直接断开。
- 内核按 manifest 的 `capabilities` 与 `plugin_grants` 决定能否把某个方法发给插件；
  `plugin.describe` / `plugin.health.check` / `plugin.channel.disable_and_restore` 属内部方法，不占能力。
- 30s 心跳；调用超时默认 10s（通道写 90s）；每插件在途上限 8 条；崩溃退避 1s/5s/30s。
- 失败统一 `{code:-32000, message, data:{code}}`。

## 3. 一次对话的数据流

1. 用户输入 → renderer 调 `chat.send`（带 client 生成的事件 id，用于幂等）。
2. 主进程经命名管道把 `chat.send` 发给内核 → `services/chat.ts`：写 `messages`、`turns`，
   校验同意声明与 owner 状态，扣预算。
3. 上下文装配：人设/关系/未闭合话题/近期情节（`memory/retrieval.ts`、`memory/actr.ts`），
   必要时走 `kernel.context.assemble`。
4. LLM 调用：优先内置兜底客户端（`llm/client.ts`）；若启用 `core.llm-router`，转发到
   OpenAI 兼容 API（`plugin.llm.generate`）。成本写 `cost_ledger`，超月预算硬拒绝。
5. 表达：按"1–3 条、每条 ≤25 字"分条；动作先隔离 800ms（`ACTION_QUARANTINE_MS`）再入
   `action_queue`，防连点/误发。
6. 记忆：回复后触发抽取（`memory/extraction.ts` + 可选 `core.memory-extract` 插件），
   候选落 `memory_episodic` / `memory_semantic` / `memory_open_loops`；**抽取不写 persona**。
7. 下发：本机对话直接推 renderer；外部通道由对应插件 `plugin.channel.send`（需租约），
   发不出去退化 App 内通知，不重试外发。
8. 全程写 `audit_log`；插件启停、授权、危险操作都有记录。

## 4. 为什么内核是唯一 SQLite 写入者

- SQLite 单写者模型最简单可靠：多进程写同一文件会争锁、产生 `SQLITE_BUSY`，WAL 也挡不住写冲突。
- 内核是单进程、单实例（客户端启动时拿单实例锁），用 `node:sqlite` 同步 API + `BEGIN IMMEDIATE`
  事务；跨模块的写操作在同一事务里，崩溃可回滚（`db/database.ts`）。
- 插件是第三方代码，不能给它数据库路径；它要写数据只能调内核方法（`kernel.memory.remember` 等），
  由内核做校验、授权与审计。这样"插件写脏数据"在结构上就不成立。
- 客户端只读：renderer 通过 `state.snapshot` / `memory.*` 等查询接口拿数据，不直连数据库。
- 导出/备份也由内核做（`export.bundle`），避免外部进程在写事务中间拷贝出半份数据。

## 5. 目录结构

```
packages/
├─ shared/     类型、zod 校验、错误码、IPC 方法表、常量（无 IO）
├─ kernel/     内核：db / memory / mind / services / plugins / ipc / llm
└─ client/     Electron：main / preload / renderer(React) / build(图标)
plugins/
├─ _sdk/plugin-runtime.mjs   零依赖插件运行时
├─ core.*                    内置功能插件
└─ channel.wechat-replica    通道骨架（默认禁用、未就绪）
scripts/       build-kernel.mjs、check-boundaries.mjs、validate-plugins.mjs、
               package-check.mjs、make-icon.py
docs/          架构、规范对照、插件、安全、M0 范围、同意声明、验收
.github/       CI
```
