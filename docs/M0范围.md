# M0 / v0.1 范围

一句话：**v0.1 是可运行的本地单机闭环骨架**——聊得起来、记得住、能导入导出、插件能装能停，
但微信通道只是"未就绪骨架"，没有云端、没有多端、没有真实语音/图片供应商。

## 1. 做了什么

| 模块 | 现状 |
| --- | --- |
| 数据层 | SQLite（`node:sqlite`）schema v1，30+ 表，`PRAGMA user_version` 迁移；时间统一 UTC 毫秒 |
| 同意声明 | 九条逐条勾选、版本化（`2026-10.1`）、撤回后写操作 `ECONSENT` |
| 对话 | `chat.send` → turns → 上下文装配 → LLM → 分条/节奏 → 落库；幂等事件 id |
| 记忆 | 规则抽取（时间/数字/人名/承诺/否定/情绪/未闭合话题）+ ACT-R 式检索 + 未闭合话题表；抽取不写 persona |
| 主动 | 驱动力（孤独/无聊/想念…）与主动时机骨架，动作 800ms 隔离 |
| 成本 | 每次调用记账；月预算默认 ¥45，超预算 `EBLOCKED` |
| 客户端 | Electron + React：同意闸、对话、记忆详情、搜索、管理抽屉（owner/persona/插件/通道/记忆） |
| 插件 | 7 个内置插件 + `_sdk` 运行时；默认拒绝、能力授权、声明闸、体检、租约、崩溃退避 |
| 打包 | `electron-builder` 配置、图标、`package-check` 自检、CI（构建/边界/插件校验/测试） |
| 安全 | 插件密钥 AES-256-GCM、日志脱敏、审计日志、本地数据不上传 |

## 2. 没做什么（以及为什么）

| 没做 | 说明 |
| --- | --- |
| 微信通道可用 | `channel.wechat-replica` 是**空的适配器骨架**，健康检查返回 `blocked`。Anteros 不自带、不内置任何注入/逆向/绕过手段；需要用户自行安装并授权第三方组件。默认禁用。 |
| 云端 / 账号 / 多端同步 | v0.1 是单机闭环，数据只在本机；没有服务器，也没有登录。 |
| 安卓 / iOS | 不做。 |
| LLM 小模型分类器 | 记忆抽取用规则（正则/关键词/句式），不调用小模型；召回不用 embedding，用关键词 + 时间衰减 + ACT-R。 |
| 向量库 / embedding | 未接；`embedding.encode` 能力预留但未启用。 |
| 真实语音/图片生成 | `core.media` 未配置时返回 `blocked`，已配置也不假成功（v0.1 不接供应商实现）。 |
| 新闻抓取 | `core.world-info` 的 `news` 返回 `degraded`，不抓取。 |
| 系统托盘 / 原生通知 | 客户端主进程当前没有 Tray/Notification 代码；`core.tray-notify` 只把通知转成内核事件。 |
| 插件市场 / 自动更新 | 无；插件是本地目录。 |
| OS 级插件沙箱 | 无（AppContainer/Job Object 在范围外）；插件声明是授权与审计层约束，不是强制隔离。 |
| 真 DPAPI | 用「本机 master key + AES-256-GCM」代替，代码与文档都如实说明。 |
| macOS / Linux | 只做 Windows 10/11 x64。 |
| 安装包签名 | 未签名；发布前需要代码签名证书。 |
| 规范 6 契约测试 10 条 | 未全部补齐；当前有 manifest 校验、边界扫描、开发期插件 mock 冒烟。 |
| 导出/导入的完整格式与回滚 | 入口在，格式与失败回滚待补。 |

## 3. 当前构建状态（诚实记录）

- `npm run build:shared`：通过。
- `npm run build:kernel`：**尚未通过**——`app.ts` 引用的 `expression/service.ts` 还没落盘（内核组在写；
  其余 `mind/service.ts`、`services/channels.ts`、`services/export.ts`、`services/plugins.ts` 已落盘）。
- `npm run build:client`：依赖内核产物，暂不能端到端跑。
- `scripts/check-boundaries.mjs`：仍有 10 处违例（内核/共享层的命名与声明文案），CI 该步骤会失败，等 lead 处理。
- `scripts/validate-plugins.mjs`：7/7 通过。
- `scripts/package-check.mjs --repo-only`：会报 `packages/client/out` 与 `packages/kernel/dist/kernel.mjs` 缺失（未构建）。

## 4. 下一步

1. **闭合构建**：补齐缺失的 service，跑通 `build:kernel` → `build:client` → `package-check`。
2. **契约测试**：把规范 6 的 10 条落成 vitest；插件 SDK 冒烟固化为仓库内测试并进 CI。
3. **边界清零**：把 `wechat_id` 等通道名从内核/共享层挪到通道插件或配置键，让 `check-boundaries` 归零。
4. **真 DPAPI**：原生扩展或 Node-API 模块，替换 master key。
5. **通道适配器接口**：定义第三方组件侧协议（不自带实现），把 `blocked` 骨架变成可插拔接口。
6. **召回升级**：embedding + 本地向量索引（可选模型，仍不出本机）。
7. **发布工程**：安装包构建、签名、自动更新（可选）、崩溃上报（默认关闭、脱敏）。
