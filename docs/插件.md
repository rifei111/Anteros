# 插件开发

插件是**独立进程**，通过命名管道和内核说 JSON-RPC。它不能直接读数据库、不能 require 内核代码、
不能拿 UI 对象；能做什么由 manifest 声明 + 用户授权共同决定。

## 1. 目录结构

```
plugins/
├─ _sdk/plugin-runtime.mjs     # 零依赖运行时（内核自带，插件共用）
├─ core.tray-notify/
│  ├─ plugin.json              # manifest（目录名必须等于 id）
│  └─ index.mjs                # 入口（entry.command）
└─ ...
```

`plugins/` 整个目录会被 electron-builder 作为 `extraResources` 打进安装包；内核启动时扫描这个目录，
读 `plugin.json`、做校验、按 `enabled` 决定是否拉起。

## 2. manifest 字段

```json
{
  "id": "core.tray-notify",
  "name": "托盘通知桥",
  "version": "0.1.0",
  "kernel_api": ">=1.0 <2.0",
  "kind": "channel",
  "description": "把 plugin.notify.send 转交内核事件……",
  "entry": { "command": "index.mjs", "args": [] },
  "capabilities": [],
  "permissions": [],
  "risk_level": "low",
  "enabled": true,
  "healthcheck": { "method": "plugin.health.check", "interval_ms": 30000, "timeout_ms": 5000 }
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 3–64 字符，小写，`^[a-z0-9][a-z0-9.-]*$`；必须与目录名一致 |
| `name` | 是 | 展示名（中文可以） |
| `version` | 是 | semver，如 `0.1.0` |
| `kernel_api` | 是 | 兼容范围；主版本必须含 1，推荐 `">=1.0 <2.0"` |
| `kind` | 是 | `channel` / `provider` / `processor` / `media` / `world` / `ui` / `ops` |
| `description` | 是 | ≤400 字；写清楚插件做什么、不做什么 |
| `entry.command` | 是 | 相对插件目录的 `.mjs` 文件；`args` 可选 |
| `capabilities` | 是 | 要调用的内核能力，见第 3 节；空数组表示不调能力 |
| `permissions` | 是 | 进程/文件/网络/密钥等权限，默认全拒 |
| `risk_level` | 是 | `low` / `medium` / `high`；high 必须同时给 `resources` 与 `healthcheck` |
| `enabled` | 否 | 首次入库的默认值；high 缺省 `false`。**不是** zod schema 字段，宿主直接读原始 JSON |
| `config_schema` | 否 | 插件配置的 JSON Schema 描述（UI 用） |
| `secrets` | 否 | 需要的密钥名；值经内核加密存储，启动时以 `ANTEROS_SECRET_*` 注入 |
| `resources` | 否 | `max_memory_mb` / `max_cpu_pct` / `call_timeout_ms` |
| `healthcheck` | 否 | `method` / `interval_ms` / `timeout_ms`；high 风险必填 |
| `min_os` | 否 | 最低系统版本 |

校验实现：`packages/shared/src/manifest.ts`（zod）。跑 `node scripts/validate-plugins.mjs` 会调用同一份
`validateManifest`，并额外检查目录名、enabled、entry 文件存在与红线。

## 3. 能力（capabilities）与权限（permissions）

能力决定**插件能被内核调用什么方法**；权限决定**插件进程本身能碰什么系统资源**。

| 能力 | 对应方法 | 说明 |
| --- | --- | --- |
| `llm.generate` | `plugin.llm.generate` | 代理一次 LLM 生成（内核有兜底客户端） |
| `extract.memory` | `plugin.extract.memory` | 从文本抽候选记忆（只产出候选，不写库） |
| `media.speak` / `media.image` | `plugin.media.speak` / `plugin.media.image` | 语音/图片生成，未配置时返回 blocked |
| `world.info` | `plugin.world.info` | 时间/天气/新闻，拿不到就 degraded |
| `ui.panel` | `plugin.ui.panel.render` | 返回只读看板 JSON 块 |
| `channel.read` | `plugin.channel.read_since` | 读外部通道增量消息 |
| `channel.history` | 历史回读（适配器实现） | 通道历史 |
| `channel.write` | `plugin.channel.send` | 向外发消息；必须同时声明 `channel.lease` |
| `channel.lease` | `plugin.channel.lease.begin/end` | 写动作独占租约 |
| `channel.media` | `plugin.channel.download_media` | 下载媒体 |
| `embedding.encode` | （预留，v0.1 未启用） | 向量化 |
| `ops.host` | （预留，v0.1 未启用） | 宿主运维 |

权限白名单（写错一个整份 manifest 会被拒绝）：

| 权限 | 类型 | 说明 |
| --- | --- | --- |
| `ui.foreground` | 普通 | 允许把客户端窗口置前（高危，需二次确认） |
| `kernel.events` | 普通 | 订阅内核事件 |
| `kernel.config` | 普通 | 读本插件配置 |
| `fs.read:<路径>` | 参数化 | 读指定路径 |
| `fs.write:<路径>` | 参数化 | 写指定路径（高危） |
| `proc.read:<进程名>` | 参数化 | 读指定进程信息（高危） |
| `proc.patch:<进程名>` | 参数化 | 修改指定进程内存（**v0.1 不提供任何实现**，仅通道骨架声明用） |
| `net.allow:<域名>` | 参数化 | 只允许访问指定域名 |
| `secrets.read:<密钥名>` | 参数化 | 读指定密钥（高危） |

授权规则（`packages/kernel/src/plugins/grants.ts`、`host.ts`）：

- **默认全拒**：`plugin_grants` 没有有效行就 `EPERM`/`EGRANT`。
- 启用插件不等于授权能力；owner 必须逐项授权。
- 含 `channel.write` 的插件，启用闸要求先有 `channel.lease` 授权。
- 授权/撤销写审计日志。

管理面板里的两个入口（都在「插件」页签）：

- **授权**：勾选清单来自 `PluginInfo.grantable`（capabilities ∪ permissions），所以 `channel.lease` 这类
  能力项也能勾；高危项标红。`proc.*`、`secrets.read:*`、`fs.write:*`、`ui.foreground`、`channel.write`
  这类需要一次性确认 token（`confirm.token` → `plugins.grant` 带 `confirmToken`）。
- **密钥**：manifest 里 `secrets` 非空的插件才会出现这个按钮；逐项密码框 → `plugins.secret.put`，
  已存在时显示「已录入，留空则不改」，删除走 `plugins.secret.delete`。
  密钥只写本机 SecretStore（AES-256-GCM，`data/secrets/<plugin-id>/<name>.bin`），审计只记名字与长度，
  不记值；`PluginInfo.missingSecrets` 每次实时重算，缺密钥的插件启用闸会拦（`EBLOCKED`）。

注意：RPC 方法名是 `plugins.grant` / `plugins.enable` / `plugins.secret.put`，宿主内部消费的 action 名是
`plugin.grant` / `plugin.enable`，两边由 `permissions.normalizeConfirmAction()` 归一，所以界面用哪种叫法都能对上。

### 两道闸的判定规则不一样，别混着用

| 字段 | 含义 | 内核判据 |
| --- | --- | --- |
| `PluginInfo.grantNeedsConfirm` | 授权要不要一次性 token | 勾选的条目里有没有命中 `^(proc\.\|secrets\.read:\|fs\.write:\|ui\.foreground$)` |
| `PluginInfo.enableNeedsConfirm` | 启用要不要一次性 token | `manifest.riskLevel === "high"` |

所以 `core.llm-router`（中风险）**授权要 token、启用不用**：它声明了 `secrets.read:llm.api_key`，
勾这一项就触发授权闸。界面按这两个字段决定弹不弹确认，不要用 `riskLevel` 自己推。

## 4. 生命周期与错误码

```
registered（已入库）
   ├─ disabled（用户停用 / 默认禁用）
   ├─ blocked（声明闸未过 / 缺密钥 / 缺租约 / 版本不兼容）
   └─ enabled → running（握手成功、心跳正常）
                    ├─ degraded（心跳失败、体检不 ok）
                    └─ crashed（连续崩溃，退避后重试）
```

- 内核为每个启用插件 `spawn` 一个 Node 进程，注入 `ANTEROS_PIPE_NAME`、`ANTEROS_TOKEN`、
  `ANTEROS_PLUGIN_ID`、`ANTEROS_DATA_DIR`、`ANTEROS_SECRET_*`。
- 30s 心跳；连续失败标 degraded，写操作直接拒绝。
- 崩溃按 1s/5s/30s 退避重启；连续失败标 crashed 并告警，内核与聊天不受影响。
- 停用：先发优雅退出，超时 kill；通道类插件必须实现 `disable_and_restore`。

插件返回给内核的错误统一是：

```json
{ "code": -32000, "message": "人类可读的中文原因", "data": { "code": "EBLOCKED", "hint": "..." } }
```

| 错误码 | 场景 |
| --- | --- |
| `EBLOCKED` | 未配置/未就绪/被闸拦住（不要重试） |
| `EDEGRADED` | 能工作但质量降级（如天气无网络） |
| `EPERM` / `EGRANT` | 没声明或没授权该能力 |
| `EMANIFEST` | manifest 校验失败 |
| `EVERSION` | kernel_api 不兼容 |
| `ETIMEOUT` | 调用超时 |
| `ECRASH` | 插件进程断了 |
| `EINVALID` | 参数错误 |
| `ENOTFOUND` | 方法未实现 |
| `EIO` | 网络/IO 失败 |
| `EUNKNOWN` | 兜底，不要把敏感信息塞进 message |

## 5. 用 `_sdk` 写一个插件

`plugins/_sdk/plugin-runtime.mjs` 已处理连接、握手、心跳、重连、错误封装、日志脱敏；
你只需要提供 handlers。

```js
// plugins/example.echo/index.mjs
import { createPlugin, fail } from "../_sdk/plugin-runtime.mjs";

// createPlugin 会立即开始连接内核（由内核拉起，不要单独 node 运行）
const plugin = createPlugin({
  id: "example.echo",
  capabilities: ["ui.panel"],
  handlers: {
    "plugin.health.check": async () => ({
      ok: true,
      status: "ok",
      message: "echo 插件正常",
    }),

    "plugin.ui.panel.render": async ({ panelId }, ctx) => {
      if (panelId !== "echo") throw fail("EINVALID", `未知面板：${panelId}`);
      const cfg = await ctx.call("kernel.config.get", { keys: ["echo.prefix"] }, { timeoutMs: 5_000 });
      return {
        title: "Echo",
        blocks: [
          { type: "heading", text: "Echo 面板" },
          { type: "text", text: `前缀：${cfg?.config?.["echo.prefix"] ?? "(未配置)"}` },
        ],
      };
    },
  },
});
```

要点：

- `createPlugin({ id, capabilities, handlers, onReady })` 返回 runtime，并**自动开始连接**；`id` 必须与目录名、manifest 一致。
- `handlers[method]` 可以是 async，签名为 `(params, ctx)`；抛 `fail(code, message)` 会变成标准错误帧。
- 回调内核用 `ctx.call(method, params, { timeoutMs })`（如 `kernel.config.get`、`kernel.audit.log`、
  `kernel.metrics.emit`）；`runtime.stats()` 可拿连接状态/心跳统计。
- 密钥用 `readSecret("llm.api_key")`，对应 manifest 的 `secrets: ["llm.api_key"]` 与权限
  `secrets.read:llm.api_key`；**不要**把密钥写进日志、配置或返回值。
- 未捕获异常 SDK 只记录不退出，内核会按心跳判 degraded；但不要依赖这个兜底。
- 能力是白名单：没在 manifest 声明的能力，内核根本不会把对应方法发给你；即使发了也会被宿主拒绝。
  这样"插件越权"在协议层就不成立。

## 6. 内置插件

| id | kind / risk | 默认 | 职责 |
| --- | --- | --- | --- |
| `core.llm-router` | provider / medium | 禁用 | 把 `plugin.llm.generate` 转发到 OpenAI 兼容 API；未配置时 EBLOCKED，内核用兜底客户端 |
| `core.memory-extract` | processor / low | 启用 | 规则抽取候选记忆（时间/数字/人名/承诺/否定/情绪/未闭合话题），不写库、不写 persona |
| `core.media` | media / medium | 启用 | 语音/图片占位；未配置返回 `blocked`，不假成功 |
| `core.world-info` | world / low | 启用 | `time`（真实本机时间/农历近似/节气近似）、`weather` 未配置或无网 degraded、`news` 不做 |
| `core.tray-notify` | channel / low | 启用 | 把通知转交内核事件，由客户端渲染；不重试 |
| `core.dashboard` | ui / low | 启用 | 只读看板 JSON 块（运行时长/插件健康/成本），不读数据库 |
| `channel.wechat-replica` | channel / high | 禁用 | **未就绪适配器骨架**：无注入、无内存偏移、无逆向；health 返回 blocked，需要用户自装第三方组件 |

## 7. 运行环境（runtime_env）

有些插件本身很轻，但它要跑起来需要一份外部运行环境（例如第三方客户端适配器）。这类插件在 manifest 里写：

```json
{ "runtime_env": true }
```

内核会为它多开一组 RPC（`plugins.runtime.status|check|install|uninstall|feed`），客户端在插件卡片下渲染「运行环境」面板。
安装器做的事只有四步，任何一步失败都保留旧版本：

1. 取清单：从更新源读 `feed.json`（默认是 GitHub Release，也可换 `file:///` 或自建 https）；
2. 下载：清单里给了整包（`archive`）就下整包，给了逐文件清单（`files` + `filesBaseUrl`）就按 `sha256` 命名逐个下载；
   **本地已存在且哈希一致的文件直接复用**，所以升级时只下载变了的文件；
3. 校验：每个文件都比对 SHA-256，清单与磁盘对不上就整次作废；
4. 切换：解到 `plugin-runtime/<pluginId>/<version>.tmp`，再原子重命名成正式目录，旧版本目录在新版本就位后才删。

清单格式（`feed.json`）：

```json
{
  "schema": 1,
  "pluginId": "channel.wechat-replica",
  "package": {
    "version": "1.1.0",
    "entry": "adapter/host.mjs",
    "archive": { "url": "https://…/wechat-replica-1.1.0.tar.gz", "sha256": "…", "size": 1126, "format": "tar.gz" },
    "files": [{ "path": "adapter/host.mjs", "sha256": "…", "size": 412 }],
    "filesBaseUrl": "https://…/runtime-feed-v2"
  }
}
```

安全边界：只接受 `http`/`https`/`file` 三种协议；拒绝 `../` 与绝对路径；清单上限 8MB；
插件目录之外不可见；安装只写 `plugin-runtime/` 下自己的目录，不碰聊天数据。

## 8. 校验与自测

```powershell
node scripts/validate-plugins.mjs    # manifest + 目录 + 红线扫描
node scripts/package-check.mjs --repo-only   # 打包资源与插件目录自检
```

提交前至少跑这两个；CI 会跑 `validate-plugins` 与 `check-boundaries`。
