## A 整块没做

### A-1 数字身体 L2 / L3 / L4（草案 6.4–6.6，附录 46–48，P1/P2）

它自己的设备、信息流、痕迹面、共同经历，全部只有设计。

- 证据：`packages/kernel/src/db/schema.ts` 建了 `device_feed` 表，但除 `services/reset.ts` 的删除清单外，全仓没有任何读写。
- 现状：它的"外界"只有 `plugins/core.world-info` 给的时间/天气/新闻，加上用户说的话。

### A-2 L1 感知现实（草案 6.3，附录 45，P1）

三层克制规则（变化时提 / 与用户有关 / 每 N 轮一次）没有输入源可克。

- 证据：全仓没有剪贴板、前台窗口、日程日历的读取（`grep clipboard|GetForegroundWindow` 在 kernel 内无业务命中；`host.ts` 里那处 `剪贴板` 只是停用通道时的还原提示）。
- 现状：`presence_state` 记的是"用户在不在、忙不忙"，不是"他在看什么"。

### A-3 可见足迹：主页 / 歌单 / 收藏（草案 3.4、6.4，附录 24，P1）

- 证据：无对应表、无插件、无 RPC。
- 现状：分享欲有（`memory/...` + 主动消息的 `share` 理由），但"分享的东西"来自记忆里的原话，不是它自己的生活产物。

### A-4 图像能力：生图 / 看图（草案 6 章数字身体的感知臂）

- 证据：`plugins/core.media` 的 manifest 声明了 `media.image`，`host.ts:246` 也映射了 `plugin.media.image`，但插件实现里 v0.1 明确写"未接入任何媒体供应商"；`services/models.ts` 的注释提了"看图和生图"，实际路由只有 reply/proactive/extract/speech。
- 现状：语音条（TTS + 虚拟声卡）已通，图像一条没通。

### A-5 行为指标与实验评估（草案 9 章，附录 51、52，P1）

- 证据：没有会话时长/次留/分享深度的采集，没有看板聚合。`plugins/core.dashboard` 是"插件页看板"，不是行为指标。
- 现状：`hazard_samples` 在记影子样本，但没有任何读取它的评估脚本。

## 如果只补三条

按"出事概率 × 修起来多便宜"排：

1. **B-13 微信版本自检**：微信一升级就可能把写路径打坏，而现在的失败方式是"发了没反应"。加一个版本区间判断 + 写路径拒绝 + 读路径降级，是几行代码的事。
2. **B-1 记忆探针测试集**：后面要调 ACT-R 参数、要判断"记忆有没有变差"，现在没有基线可比。
3. **C-1/C-2 选择账本与曝光记账的写入**：表和接口都在，只差写入点；补上之后，完全体切换与随机探索才有据可查。

其余的（数字身体、足迹、行为指标）建议等真机用出问题再动——它们吃工期，但不解决"现在能不能用"。
