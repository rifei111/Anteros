# v1.0.6

修「私聊不回」和「同一条消息发两遍 / 搜索白名单用户的工作做两次」。

## 根因（都在通道层）

1. **一次发送会卡住整条通道。** 界面驱动（uiautomation / WinRT）卡在 C 层时占着 GIL，旁路进程里那个
   「看门狗线程」抢不到 CPU，连巡检都停，表现就是回完群聊之后私聊彻底没反应。现在每次发送/预热都
   丢到**独立子进程**里做，超时（发送 20 秒、预热 25 秒）直接杀掉子进程，主进程只损失这一次操作。
2. **微信窗口被最小化或挪到屏幕外时必然卡。** 实测窗口矩形是 (-31991, -32000)。发送前先恢复窗口
   并拉到前台再操作。
3. **「数据库未确认」被当成失败，于是重发一遍。** 上游通常等 8 秒回一句「消息已操作发送，但数据库
   未确认」——消息其实已经发出去了。旧代码当失败后换目标再发，群里就看到同一条出现两次。现在已操作
   发送就算成功，不再重发。
4. **会话被搜索两次。** 之前先 open_chat 再 send_msg(who=...)，上游会把会话再搜一遍。现在打开会话后
   直接在当前会话粘贴发送，只搜一次（实测 6.5 秒/条，之前 10–20 秒）。

## 验证

- 直接驱动旁路进程实测三次：`{"ok": true, "status": "成功"}`，最后一次 6.5 秒，窗口矩形恢复正常。
- npm test 122 用例全绿；smoke 96 项全过；package-check 25 项全过。
- 包内 sidecar.py 与源码 SHA-256 一致。

## 仍然存在的限制

- 每次发送是冷启动子进程，约 5–7 秒；换来的是「一条卡住不会拖死整条通道」。
- 群聊里「自己决定回不回」还没有在真实群里观察过。
